# ChargeCap 0.6.6 — 退出时解除充电控制

macOS 13+ / Apple Silicon / SwiftUI + AppKit。保留 ChargeCap 0.4.9 的叶子图标（单色或绿色）、主面板布局、动态高度、电池功率显示、组件图形化安装与独立卸载器；仅重构充电控制交互与指令执行层。

项目由 [MauriceLiang/MauLeaf](https://github.com/MauriceLiang/MauLeaf) 仓库维护，应用名称保持 ChargeCap。安装包及各版本更新内容见 [GitHub Releases](https://github.com/MauriceLiang/MauLeaf/releases)。

## 为什么重写「充满一次」？

上游官方 `batt v0.8.0` 的命令注册代码不包含 `charge full`，尽管当前上游 master 分支文档描述了这个功能。旧版 ChargeCap 错误地调用了不受固定版本支持的指令。因此 0.5.0 不再执行 `batt charge full`，也不偷偷拉取不稳定的上游代码。

0.5.0 使用 v0.8.0 已有的 `batt disable --for=10h` + 用户 LaunchAgent 恢复检查器来实现近似的「仅充满一次」：

1. 先确认 `batt status` 可用，记录用户之前的限充值。
2. 通过 LaunchAgent 注册独立的 `ChargeCapOnceHelper`，每 20 秒检查 `pmset -g batt`。
3. 执行 `batt disable --for=10h`，允许充电至 100%；batt 自身在期限到达时自动恢复原充电限制（即使重启）。
4. 电量达到 100% 后检查器执行 `batt limit <原上限>` 并通过 `batt status` 确认，随后删除这次任务。
5. 监控独立于面板刷新运行；从 0.6.6 起，正常退出主应用会取消任务、解除限充并取消 batt 的定时恢复。若异常结束应用、休眠或未登录，检查可能暂缓，原有 10 小时恢复仍作为异常场景的兜底。

**限制**：由于 macOS 休眠时用户态检查器不会实时运行，此实现不能保证到达 100% 的瞬间立刻停止；满电后通常在下一次检查时恢复。长时间睡眠/退出登录后以 batt 的限时恢复为安全兜底。因此这是 **0.5.0 的兼容实现**，并不等价于最新版 batt 内置的持久化 one-time charge。对精确要求极高的用户，应等待验证过的内置新版本后替换此兼容层。

## 用户操作

- **自动更新**：启动应用和打开菜单栏面板时自动读取状态，运行期间继续自动更新；不再显示底部常驻状态行和「刷新状态」按钮，操作失败时仍显示错误提示。
- **操作提示**：切换上限、充满方式等操作的提示显示在底部操作栏上方的悬浮条中，不参与内容高度计算；顶部不再插入提示，滑块下方也不再显示会换行的动态状态。处理中显示进度，成功约 2 秒后淡出；失败保留摘要、详情和关闭入口，限充或充满操作失败时可重试。
- **窗口收起**：点击窗口外或再次点击菜单栏图标可收起面板；确认弹窗打开或操作进行中时保留窗口，避免中断授权交互。
- **退出应用**：退出按钮和系统正常退出请求都会先等待当前操作结束、取消单次充满与主动降电量任务、恢复适配器供电，再执行 `batt disable` 并读取状态，确认上限为 100% 且没有定时恢复计划后退出。失败则取消退出并保留错误提示；再次点击「退出」可重试。`batt` 服务保留安装并处于不限充状态。下次启动时重新应用已保存的模式和上限；取消的单次充满任务不会自动重启。收起面板不等于退出。
- **实时电池功率**：面板展开后立即更新，充电或放电时每 2 秒采样，未充放电时放慢至每 5 秒。收起面板即停止额外功率采样，保留 20 秒后台状态检查和独立安全监控。电源类型变化、系统唤醒、模式或上限操作结束后及时更新。
- **采样开销**：快速功率读取使用原生 IOKit，在后台执行，不启动 `ioreg`、`pmset` 或 `batt` 子进程；同一时间只允许一轮采样，窗口收起或进入睡眠后丢弃尚未完成的旧结果。只有变化的显示值才更新，菜单栏图标资源也仅在样式改变时重新载入。支持有符号及无符号 64 位电流；缺少有效读数时显示「—」。
- **控制模式**：50–95% 上限，拖动滑块停止约 450ms 后自动提交；点击预设值立即提交。没有「应用上限」按钮。返回成功后再次读取 `batt status`，确认设备报告的上限与目标一致。输入连续变化时只提交最终目标，避免产生大量指令。
- **直接充满 / 仅充满一次**：创建后台任务，再限时解除限充；100% 时恢复此前上限，或手动选择「取消本次充满」恢复。`batt` 组件必须允许非 root 客户端访问服务（ChargeCap 的一键安装默认启用该权限）。
- **当前已经 100%**：进入「直接充满」后保留充满方式选项，原限充上限继续生效，不创建重复任务；可以选择「持续允许充满」。电量下降后，可点击「启动仅充满一次」。
- **直接充满 / 持续允许充满**：执行 `batt disable`，复读 `status` 确认上限为 100%；回到控制模式时恢复用户保存的上限。
- **超过上限时 / 保持适配器供电**：默认策略。应用限充值并保持适配器供电；电量高于上限时不主动消耗电池。
- **超过上限时 / 主动使用电池，降至上限**：确认设备支持适配器控制、上限已生效、适配器已连接及安全读数正常后，启动独立后台监控。达到上限后自动恢复适配器供电；修改上限会更新后台目标。电量不高于上限时不主动放电，仍正常限充。
- **充满后的暂停**：进入充满模式前先停止主动放电并恢复供电。单次充满结束后恢复原限充值、返回控制模式，并暂缓主动放电；暂停状态在重启应用后仍保留。点击「恢复主动降电量」才恢复主动策略。
- **切换时序**：不会在 UI 点击时提前报告成功；操作中锁定互斥动作、在命令返回后读取状态、失败显示错误。不会删除 Homebrew 管理的 `batt`。

## 主动降电量与保护

监控复用包内 `ChargeCapOnceHelper`，以 `--discharge` 模式运行，每 20 秒检查一次。每次只执行 `batt adapter disable --for=1m`：batt 在断供前持久化恢复期限，正常运行的 daemon 会在期限到达时恢复适配器；这与监控主动恢复相互独立。相关固定版本实现见 [batt v0.8.0 handlers.go](https://github.com/charlie0129/batt/blob/v0.8.0/pkg/daemon/handlers.go) 和 [loop.go](https://github.com/charlie0129/batt/blob/v0.8.0/pkg/daemon/loop.go)。

- 达到上限：恢复适配器、完成任务；之后修改上限仍按原策略处理。
- 合盖、温度不在严格的 `0 < 温度 < 45°C` 范围内、安全读数失效、设备能力或限充值变化、运行达到 4 小时：停止续期、恢复适配器并暂停；用户可以检查后手动恢复。
- 命令失败或状态未验证：显示失败。恢复未确认时保留任务，后台重试恢复，不继续续期停供。
- 主应用运行期间，监控独立工作；监控崩溃由 launchd 重启。正常退出主应用会停止监控并恢复供电。取消与后台控制通过跨进程文件锁串行执行，避免迟到的后台指令在退出后重新写入限制。

**运行边界**：合盖断供可能让外接屏模式进入睡眠。用户态监控和 batt daemon 在系统睡眠、关机或服务未运行期间无法保证即时执行；定时恢复会在 daemon 恢复运行后处理。因此「1 分钟」是给 batt 的停供期限，不是所有系统状态下的实时恢复保证。不会修改系统睡眠设置来绕过这一限制。

## 开发构建

1. 解压到本地，在 Apple Silicon Mac 上运行 `./build.command`。
2. 如果之前已经成功构建过 `0.4.9`，可复制其 `Vendor/batt` 和 `Vendor/batt.sha256` 到对应目录以离线复用，版本要求 v0.8.0。
3. 构建脚本使用 Xcode Command Line Tools：在隐藏临时目录编译 `ChargeCap.app`、`Uninstall ChargeCap.app` 和独立后台程序 `ChargeCapOnceHelper`，嵌入叶子图标、完成签名后输出应用并刷新系统注册，然后生成 `ChargeCap-0.6.6.dmg`。版本号和构建号统一维护于 `build.command` 的 `APP_VERSION`、`APP_BUILD`。
4. 构建后先退出旧版 ChargeCap，使用新版替换。正常工作的 `batt` 后台服务无需重装。
5. 新的单次充满任务会复制后台程序到用户的 `~/Library/Application Support/ChargeCap/ChargeCapOnceHelper` 并注册 `~/Library/LaunchAgents/dev.mauriceliang.chargecap.once.plist`，不会要求用户运行安装命令。
6. 主动降电量会复制同一后台程序为 `ChargeCapDischargeHelper` 并注册 `~/Library/LaunchAgents/dev.mauriceliang.chargecap.discharge.plist`。任务、结果和暂停记录保存在同一个 Application Support 目录；卸载前先恢复供电并停止任务。

## 检查和测试

`./tests/run.sh` 在具备 Swift 编译器的机器上执行纯 Foundation 测试和静态语法检查；macOS 上还使用模拟 `batt` 和后台任务测试实际 `ChargeManager` 的模式切换、原上限恢复和错误提示，不会运行硬件控制命令，不会更改 Mac 电池状态。

自动化检查包括核心断言、主动降电量与保护逻辑（含并发取消、恢复失败重试、任务文件损坏）、模拟后端的实际 `ChargeManager` 模式切换和失败重试、自适应采样间隔、窗口开关、并发去重及模拟睡眠/唤醒。离屏 SwiftUI/AppKit 布局回归还检查普通、处理中、长错误状态下的内容高度一致，覆盖悬浮层不挤动内容的行为。**实际窗口点击、实际插拔电源与睡眠通知、长期 CPU/能耗、真实充放电、合盖外接屏和 launchd 崩溃重启尚未验收**。首次使用请观察 `batt status` 及实际电池行为，不要把「任务启动」误判成硬件充电立即发生。

## 安全注意事项

- 不使用私有 SMC 写入方法。底层控制仍由开源 `batt` 承担，符合其上游 GPL-2.0 许可证。组件源码/许可证和构建校验机制不变。
- 操作要求有正常运行的 batt 服务；如果其他方式安装了受限制的 batt，普通账户可能没有控制权限，应用应显示错误而不是绕过授权。
- 一次性充满独立使用 `batt disable --for=10h` 作为异常场景的持久兜底。正常退出会取消该恢复计划并解除控制，卸载会清理 ChargeCap 注册的 LaunchAgent。
- 强制结束进程、崩溃或断电会绕过正常退出清理，batt 的持久设置可能保留。可重新启动 ChargeCap 后正常退出；不要把隐藏窗口当成退出应用。
