# 超限优先适配器：Preview 1 只读验证规格

## 用户目标

当前电量 92%，固件限充 80%，Mac 已连接适配器：希望不强制将电量从 92% 放电到 80%，而是在暂停充电的同时优先由适配器供给系统。

## 现阶段能力

MauLeaf 0.9.0 只管理 bfF0 / bfD0 / bfE0。固件限制能被写入并读回，不代表能独立选择电源路径；macOS 可能在上限之上主动消耗电池。不能把关闭限充当成“保电”，因为可能继续充电至 100%。

Preview 1 增加 **设置 → 超限优先适配器** 的本地偏好，默认关闭。开启后为纯观察模式，不改变任何寄存器、后台服务或系统策略。开关旁必须显示可见的“只读、不切换供电”说明，避免用户以为该功能已生效。

## 只读状态判定

观察样本来自 AppleSmartBattery 的 `CurrentCapacity` / `MaxCapacity` / `IsCharging` / `ExternalConnected` / `Amperage`。只对已经有 MauLeaf 原始快照且 `bfF0` 已激活、未进入本次充满、百分比**严格大于**实际 `bfD0` 上限的状态进行超限判断。

- 用户未启用监测：不做超限提示。
- 限充无效、旧版未托管、状态未知、本次充满：显示对应不适用/暂停状态。
- 未接电或电源读取未知：不推断来自适配器。
- 电量未知、未超限：按状态显示。
- `IsCharging=true` 或电池电流大于等于 +150mA：提示超限仍可能在充电，不能宣称限充正在停止。
- 电池电流小于等于 -150mA：只有连续三次**不同的电池读取**都符合条件才提示持续放电；过程期间显示观察中。
- 电流在 -150mA 至 +150mA 区间：仅提示“未检测到明显放电”，不可说“确认由适配器供电”。
- 电池电流缺失：明确显示“无法判断”。

**约束：** 每 20 秒执行一次现有定时器读取。Helper 状态同步不额外计数，防止同一次读数重复累加。设置开关本身不能写 SMC、不能自动重试写固件，且不增加驻留的特权后台任务。

## 真正供电控制的准入门槛（不在 Preview 1 中）

1. 只读探测当前特定 M1 Pro + 固件 + macOS 15 的可用电源/充电键，确认签名、长度、只读原值。
2. 使用独立受控工具与有电源保护的手工流程，证明能**停止继续充电且不断开适配器供电**。不能借用会使设备切换为电池供电的 adapter cutoff 键；不能假定 macOS 27 的 native no-drain 适用于 macOS 15 的 firmware 模式。
3. 验证插电/拔电、睡眠/唤醒、合盖、电流抖动、本次充满、退出、崩溃、断电、低电量等边界，并采集至少完整的充放电曲线。
4. 对任何新增寄存器写入建立 root 权限门控、设备白名单、原值持久化、读回、失败恢复和卸载清理。未验证设备上自动禁用。
5. 只有满足上述全部条件，才能将设置说明从“仅检测”改为“实际供电模式”，并公开宣称可用。

## 测试

`tests/AboveLimitPowerPolicyTests.swift` 覆盖纯状态逻辑；
`tests/BatteryStatusReaderTests.swift` 覆盖有符号电流解析；
`tests/ChargeManagerTests.swift` 验证偏好持久化与观察过程不触发固件写入；
`tests/FeedbackLayoutTests.swift` 测量中英文卡片展开，不允许滚动或浮层遮挡。
CI 使用模拟后端，不能替代真实供电路径验证。
