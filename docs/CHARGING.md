# 充电行为与运行边界

本文说明 MauLeaf 的充电控制、后台任务与异常场景。安装与日常使用见 [项目首页](../README.md)。

> [!NOTE]
> 从 0.8.0-preview.1 起，用户界面仅公开「充电上限」和「本次充满」。实时功率、主动放电、持续充满、登录项控制和图标样式设置已从界面移除。旧版主动放电任务会在启动时尝试停止，默认策略重置为保持适配器供电。下文仍保留旧实现的技术记录，不能将其视为当前公开功能。
>
> 自研 AppleSMC 后端目前仍为只读集成状态；真实固件写入、激活和充电限制效果尚未在目标设备完成验证。0.8.0-preview.1 的实际充电操作仍由 batt v0.8.0 执行。

## 为什么重写「充满一次」？

项目固定使用的 `batt v0.8.0` 不包含 `charge full` 子命令，应用早期曾错误调用该指令。因此应用不再执行 `batt charge full`，也不偷偷拉取不稳定的上游代码。

MauLeaf 使用 v0.8.0 已有的 `batt disable --for=10h` + 用户 LaunchAgent 恢复检查器来实现近似的「仅充满一次」：

1. 先确认 `batt status` 可用，记录用户之前的限充值。
2. 通过 LaunchAgent 注册独立的 `MauLeafOnceHelper`，每 20 秒检查 `pmset -g batt`。
3. 执行 `batt disable --for=10h`，允许充电至 100%；batt 自身在期限到达时自动恢复原充电限制（即使重启）。
4. 电量达到 100% 后检查器执行 `batt limit <原上限>` 并通过 `batt status` 确认，随后删除这次任务。
5. 监控独立于面板刷新运行；从 0.6.6 起，正常退出主应用会取消任务、解除限充并取消 batt 的定时恢复。若异常结束应用、休眠或未登录，检查可能暂缓，原有 10 小时恢复仍作为异常场景的兜底。

**限制**：由于 macOS 休眠时用户态检查器不会实时运行，此实现不能保证到达 100% 的瞬间立刻停止；满电后通常在下一次检查时恢复。长时间睡眠/退出登录后以 batt 的限时恢复为安全兜底。因此这是 **针对 batt v0.8.0 的兼容实现**，并不等价于最新版 batt 内置的持久化 one-time charge。对精确要求极高的用户，应等待验证过的内置新版本后替换此兼容层。


## 用户操作

- **当前状态**：打开面板时读取电池百分比、供电状态和控制组件状态。菜单栏固定显示绿色叶子，不再提供样式选择。
- **充电上限**：50–95% 上限，拖动滑块停止约 450ms 后自动提交；点击预设值立即提交。返回成功后再次读取控制组件状态，确认设备报告的上限与目标一致。
- **本次充满**：创建后台任务，再限时解除限充；达到 100% 后恢复此前上限，也可手动取消并恢复。batt v0.8.0 的 10 小时限时恢复是异常场景兜底；睡眠期间无法保证在到达 100% 的瞬间恢复。
- **上限调整保护**：本次充满期间锁定上限控件，避免修改用于恢复的目标值；取消任务或完成充满后重新开放。
- **操作提示**：处理中显示进度，成功提示短暂显示后淡出；失败保留摘要、详情和重试入口。提示覆盖在面板底部，不改变控件布局。
- **窗口收起**：点击窗口外或再次点击菜单栏图标可收起面板；确认弹窗打开或操作进行中时保留窗口。收起面板不会取消单次充满。
- **退出应用**：等待当前操作结束、取消单次充满任务，再按当前版本退出流程恢复默认充电状态并验证后退出。失败则取消退出并保留错误提示。下次启动会重新应用已保存的充电上限。
- **轻量采样**：当前电量与供电状态仅在面板打开时采样；不再展示实时充放电功率。面板收起或系统睡眠时停止额外采样。

## 主动降电量与保护（旧版内部实现，当前界面已移除）

以下内容仅用于说明旧版本实现。新预览版不再提供主动放电入口，默认把旧版偏好迁移为保持适配器供电，并在启动时尝试清理遗留任务。旧版监控曾复用包内 `MauLeafOnceHelper`，以 `--discharge` 模式运行，每 20 秒检查一次。每次只执行 `batt adapter disable --for=1m`：batt 在断供前持久化恢复期限，正常运行的 daemon 会在期限到达时恢复适配器；这与监控主动恢复相互独立。相关固定版本实现见 [batt v0.8.0 handlers.go](https://github.com/charlie0129/batt/blob/v0.8.0/pkg/daemon/handlers.go) 和 [loop.go](https://github.com/charlie0129/batt/blob/v0.8.0/pkg/daemon/loop.go)。

- 达到上限：恢复适配器、完成任务；之后修改上限仍按原策略处理。
- 合盖、温度不在严格的 `0 < 温度 < 45°C` 范围内、安全读数失效、设备能力或限充值变化、运行达到 4 小时：停止续期、恢复适配器并暂停；用户可以检查后手动恢复。
- 命令失败或状态未验证：显示失败。恢复未确认时保留任务，后台重试恢复，不继续续期停供。
- 主应用运行期间，监控独立工作；监控崩溃由 launchd 重启。正常退出主应用会停止监控并恢复供电。取消与后台控制通过跨进程文件锁串行执行，避免迟到的后台指令在退出后重新写入限制。

**运行边界**：合盖断供可能让外接屏模式进入睡眠。用户态监控和 batt daemon 在系统睡眠、关机或服务未运行期间无法保证即时执行；定时恢复会在 daemon 恢复运行后处理。因此「1 分钟」是给 batt 的停供期限，不是所有系统状态下的实时恢复保证。不会修改系统睡眠设置来绕过这一限制。


## 安全注意事项

- 0.8.0-preview.1 尚未将自研 AppleSMC 后端接入实际写入路径；当前底层控制仍由开源 `batt` 承担，符合其上游 GPL-2.0 许可证。组件源码/许可证和构建校验机制不变。
- 操作要求有正常运行的 batt 服务；如果其他方式安装了受限制的 batt，普通账户可能没有控制权限，应用应显示错误而不是绕过授权。
- 一次性充满独立使用 `batt disable --for=10h` 作为异常场景的持久兜底。正常退出会取消该恢复计划并解除控制，卸载会清理 MauLeaf 注册的 LaunchAgent。
- 强制结束进程、崩溃或断电会绕过正常退出清理，batt 的持久设置可能保留。可重新启动 MauLeaf 后正常退出；不要把隐藏窗口当成退出应用。


## 从 ChargeCap 升级的兼容约定

对外名称、可执行文件和资源已更名为 MauLeaf。为复用已有偏好设置、安装凭据和后台任务，以下持久标识沿用旧名称；这不影响 Finder 或界面显示的应用名称。

| 类型 | 保留的标识或路径 |
| --- | --- |
| 主应用 Bundle ID | `com.local.chargecap` |
| 卸载器 Bundle ID | `com.local.chargecap.uninstaller` |
| 用户任务与记录 | `~/Library/Application Support/ChargeCap` |
| 系统安装凭据 | `/Library/Application Support/ChargeCap/managed-install` |
| 单次充满 LaunchAgent | `dev.mauriceliang.chargecap.once` |
| 主动降电量 LaunchAgent | `dev.mauriceliang.chargecap.discharge` |

已有 UserDefaults 键也保持兼容。新任务使用 `MauLeafOnceHelper` / `MauLeafDischargeHelper`；取消与卸载仍针对上述稳定任务标识，避免旧任务遗留。独立卸载器会要求先退出新旧主应用，并清理 `/Applications` 中两种名称的主应用。升级前请正常退出旧版，不要同时运行两个版本。
