## 简体中文

### MauLeaf 0.9.0 — 正式版

MauLeaf 0.9.0 将菜单栏充电控制界面统一为一张简洁的原生圆角卡片，并保留 0.8.0 已有的按需授权、原生 AppleSMC 限充与安全恢复功能。本版仅发布 **Apple Silicon arm64 DMG**。

#### 本次更新

- **单卡片菜单栏界面：** 移除原有外层窗口边框和嵌套状态卡片。供电状态、限制充电、本次充满、充电上限、设置与退出统一显示在一张圆角材质卡片上，采用一致的图标、分割线和文字对齐。
- **直接打开与关闭：** 点击菜单栏叶子立即显示完整卡片，再次点击或点击窗口外部立即关闭。取消早期预览版的弹窗展开、缩回、代理窗口和相关形变动画，不让浮窗变成动态特效。
- **禁止面板滚动：** 移除根部 ScrollView，滚轮或触控板上下滑动不再推动整张卡片或产生回弹。展开「充电上限」「设置」及显示错误反馈时，面板仍随实际内容高度调整；这两项卡片内部展开保留轻量动画。
- **顶部直达操作：** 点击「限制充电」与「本次充满」右侧状态胶囊即可操作；供电状态为只读。充电中状态使用绿色反馈，未启用/不可用等状态保持中性。充电上限支持 50–95% 滑杆以及 70%、75%、80%、85%、90%、95% 快捷预设。
- **个性化与双语：** 默认显示三行精简状态，设置中可选择显示当前电量大数字，并即时切换中文或 English；偏好会被保留。
- **任务反馈与稳定性：** 操作进度保留在相应状态行，错误信息在卡片内显示并可查看详情或在允许时重试，不遮挡设置及退出。已补充中英文布局、非滚动卡片和无弹窗开合动画的回归检查。

#### 安全行为保持不变

- 启动与只读查看电池不会自动启用限充、安装特权 Helper 或弹出管理员授权；首次主动启用时才按需请求授权与确认。
- 开启限充前保存原始 bfF0、bfD0、bfE0 寄存器及设备身份快照；停用和正常退出按照安全条件恢复原始状态并进行读回核验。验证或清理失败时不伪装为成功，保留所需恢复信息。
- 「保留组件并退出」与「移除组件并退出」继续按当前安全流程执行；固件限制的设置与恢复逻辑没有随界面改造而更改。

#### 兼容性与注意事项

- **新建固件限充仅支持** MacBookPro18,1（Apple M1 Pro）、macOS 15、mBoot-20457.41.3 和 arm64 的已限定组合。macOS 26/27、Intel 及未经验证的设备不可用于新建限充；历史恢复操作采用独立校验。
- 真实充电停止与重新开始的百分比仍未完成全周期实机验证。寄存器写入及读回成功，不等于实际充电行为已经完全验证；**正式版不代表兼容所有硬件**。
- 安装包采用 **ad-hoc 签名，未进行 Apple Developer ID 签名或 Apple 公证**，安装时 macOS 可能提示开发者无法验证。只从本仓库官方 Release 获取。
- GitHub Actions 自动化测试使用模拟 SMC 后端，不会在 CI 设备上写入真实电池固件。

## English

### MauLeaf 0.9.0 — Stable release

MauLeaf 0.9.0 consolidates its menu-bar charging controls into one minimal, native rounded card, while retaining the on-demand authorization, AppleSMC charge-limit safeguards and restoration behavior from 0.8.0. This release ships an **Apple Silicon arm64 DMG only**.

#### What's new

- **One native floating card:** Remove the outer window frame and nested status tile. Power, Charge limit, Full charge, Charging limit, Settings and Quit now live on one rounded material surface with consistent icons, dividers and value alignment.
- **Instant menu-bar popup:** Clicking the leaf immediately shows the complete card; clicking it again or clicking outside immediately dismisses the panel. Remove the experimental entrance/exit morphs, proxy windows and spring-driven icon-to-card transitions.
- **No scrollable panel:** Remove the root ScrollView so a mouse wheel or trackpad cannot scroll or rubber-band the entire panel. The window still grows to fit Charging limit, Settings and inline error messages; subtle **in-card disclosure** animation remains.
- **Direct charging controls:** Activate or disable charging limits and temporary full charge directly from the status pills; the power row remains read-only. Charging state uses green where appropriate, and unavailable/inactive states remain neutral. The limit editor keeps the 50–95% slider plus 70%, 75%, 80%, 85%, 90%, 95% presets.
- **Optional percentage and localization:** The default compact view shows three status rows; Settings can show a large current battery percentage and switch immediately between Simplified Chinese and English. Preferences persist.
- **Clear operation feedback:** Progress appears in the relevant status control; inline errors provide details and eligible retry actions without obscuring Settings or Quit. Expanded bilingual UI layout and no-scroll/no-popup-animation regression tests are included.

#### Safety behavior unchanged

- Launch and read-only battery checks never automatically activate charging limits, install the privileged Helper or request administrator authorization. Authorization and confirmation occur only after the user explicitly enables control.
- Before the first firmware change, MauLeaf saves the original bfF0/bfD0/bfE0 values and device identity. Disabling limits and normal quit retain guarded restoration and read-back verification. Failed verification never masquerades as safe completion; recovery information is preserved as required.
- The Keep components / Remove components exit choices retain their existing safeguards. The UI redesign does not change the AppleSMC write and restore protocols.

#### Compatibility and limitations

- **New firmware charge-limit writes are restricted** to MacBookPro18,1 (M1 Pro), macOS 15, firmware mBoot-20457.41.3 and arm64. macOS 26/27, Intel and unverified configurations cannot activate new charge limits. Existing saved-state restoration uses separate identity checks.
- Actual physical charge-stop/resume percentages still need extended on-device observation. Successful register writes/read-back do not establish complete charging-behavior validation; a stable label is **not** a claim of universal hardware compatibility.
- The installer uses **ad-hoc code signing**, not Apple Developer ID signing or notarization. macOS may show security prompts; use only the official release from this repository.
- CI runs against a simulated SMC backend and never writes physical battery firmware.
