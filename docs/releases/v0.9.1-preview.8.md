## 简体中文

### MauLeaf v0.9.1-preview.8 — 轻量化供电流向卡片

参考开源项目 [Status Trio](https://github.com/lingyired/status-trio) 的原生供电图布局与绘制思路，重新实现 MauLeaf 顶部「供电详情」。使用 MauLeaf 现有的只读功率数据，不移植 Status Trio 的 SMC 传感器、后台任务或系统控制。

- **紧凑布局**：移除 Preview 7 体积过大的彩色节点与厚重外框。左侧供电源使用窄卡片，右侧采用精简目标卡片；适配器输入使用自适应银灰，电池放电橙色、充电绿色、系统靛蓝色。
- **连续曲线流带**：柔和渐变流线贴合卡片圆角边缘，使用偶奇填充遮罩切掉半透明节点内的重叠流带。
- **按功率比例呈现**：充电和电池辅助双路流带仅在样本完整、一致时按功率占比分配厚度；弱分支使用紧凑单行展示。数据缺失、相互矛盾或为零时不绘制伪造比例。
- **四种供电状态**：电池 → 系统；适配器 → 系统；适配器 → 系统与电池；适配器 + 电池 → 系统。瓦数在节点内，未知值为「—」，无重复统计行。
- **固件与性能边界**：只修改 SwiftUI 展示，保留原有 IOKit 只读数据源、XPC v6 / Helper 1.3.0、原始固件快照、拔电恢复、动态保电及本次充满策略。无新增权限、轮询、网页视图或滚动。
- **测试覆盖**：中文/英文、深色/浅色、328pt 宽度、四种模式、未知状态、缺少遥测及非法比例读数。

**真机验证边界：** 用户已在当前设备验证动态保电启用后的供电表现和拔电反馈正常，普通固定上限模式仍存在拔电状态延迟。本版仅优化 UI，不宣称解决该模式的延迟，也不将用户设备观察推广至其他设备。仍需真机视觉验收小功率支路和浅色主题。

**参考与版权：** Status Trio © 其贡献者，Apache License 2.0。MauLeaf 重新实现其紧凑节点、比例流带和遮罩接缝的设计思路。上游：[BatteryPowerFlowView.swift](https://github.com/lingyired/status-trio/blob/main/Sources/StatusTrioCore/UI/BatteryPowerFlowView.swift) · [PowerFlowCardGeometry.swift](https://github.com/lingyired/status-trio/blob/main/Sources/StatusTrioCore/UI/PowerFlowCardGeometry.swift)。

## English

### MauLeaf v0.9.1-preview.8 — Compact Native Power Flow

- Replaces the oversized Preview 7 cards with smaller source/sink metrics and adaptive neutral-silver, orange, green and indigo surfaces, inspired by the Apache-2.0-licensed [Status Trio](https://github.com/lingyired/status-trio).
- Rounded node cutouts mask the overlapping ends of smoothly tapered gradient ribbons.
- Complete and consistent readings yield proportional dual-branch ribbons; unknown, zero-total or contradictory samples never produce fabricated proportions.
- All four supply paths, local watts, bilingual status, the non-scrolling menu panel and read-only battery sampling are preserved.
- No new permissions, sampling tasks or privileged writes; Helper remains XPC v6 / build 1.3.0. Unplug restoration, Dynamic Hold, one-time full and safe uninstall are unchanged.
- Geometry checks cover 328pt, both languages, both appearances, partial data and unknown power state.

**Hardware note:** The user reports verified power behavior and unplug response with Dynamic Hold on the tested Mac, while fixed-limit mode still has unplug-state latency. This UI-only preview does not resolve that separate issue. Real-device visual QA is still required.

**Attribution:** Status Trio, Apache-2.0, https://github.com/lingyired/status-trio. The presentation code was rewritten to use MauLeaf's existing power model.
